01 · 变更摘要

以《中央音乐学院海内外考级曲目·扬琴 1–6 级》（你在用的这本）为事实基准，需求要做三件事：

变更现状目标
记谱法原型实现的是自绘五线谱（SVG 逐音点击）改为简谱渲染（数字简谱，含高低八度点、减时线、小节线），与真实教学一致
曲目库11 首自编入门曲（五声音阶练习、小星星、两只老虎……）替换为央音 1–6 级曲目库：78 首（练习曲 30 + 乐曲 48，含 25 首必弹※）[1]，按级分类排序
分级体系谱库只有「基本功 / 入门曲目」两类标签曲目挂 级别(1–6) / 类型(练习曲·乐曲) / 必弹标记；学生档案挂当前级别；选曲、作业、成长线全部按级联动
一句话：把「示范用的玩具曲库」换成了「你上课真的在教的考级曲目」，把「画出来的五线谱」换成「你和学生真正读的简谱」。

02 · 关键发现：这不是改需求，是需求回归 + 原型补课

翻 PRD 时发现一个重要事实：PRD 的 FR-M7-02 / FR-M7-03 本来就写的是简谱[2]：

FR-M7-02 谱面数据结构：「以『行 + 音符』两级结构存储……同一结构可承载简谱与扬琴技法标记」
FR-M7-03 谱面渲染：「小程序内渲染可横向滚动的简谱，支持放大、按行定位、只显示作业指定行」

偏航发生在原型实现：为了快速做出可点击的谱面，原型用了自绘五线谱 SVG。所以本次变更的定性是——

对象定性动作量
PRD小幅修订方向本来正确，补「考级分级」相关条目即可改 3 条 + 新增 3 条（§05）
原型补课渲染器与真实教学脱节，需重做简谱渲染器 + 曲目数据替换（§06–08）
曲目内容换血玩具曲库 → 真实考级曲库78 首结构化数据，分批录入（§08）

05 · PRD 修改清单（逐条）

条目改法
FR-M7-01 内置谱库重写：内置曲目库改为「央音扬琴考级 1–6 级曲目」，每首含 {grade:1–6, type:练习曲|乐曲, required:必弹|选弹, title, arranger, source_page, key:1=X, tempo_mark, default_bpm}；验收标准从「首发 ≥30 首」改为「首批 ≥12 首（分批录入策略见 §08），结构上 78 首占位、可渐进补齐」
FR-M7-02 谱面数据结构保留「行+音符」两级结构，细化简谱音符字段：{degree:1–7, octave:-1|0|1(低/中/高音点), duration:{base, dot_count, beam_count}, rest:bool}；行级补 {key_sig, tempo_mark, lyrics?}
FR-M7-03 谱面渲染保留简谱方向，补验收元素清单：高低八度点、减时线（1–3 条）、增时线（—）、休止符 0、小节线、终止线、连线、反复记号（V1 可不支持）、临时升降记号（V1 可不支持，见 §12）
FR-M7-04 谱面批注保留交互；词表升级：标记类型从现在的 6 种扩展为两层——通用标记（重点/难点/慢练/分句）+ 扬琴技法标记（轮音/反竹/弹轮/衬音/座音/滑弹/拨音……以原书 p153 技法符号表为准，由你人工核定，正好并入 T0 词表任务）
FR-M7-06 批注锚定不变：锚定 {课次,学生,曲目,谱面版本,行号,音符序号} 在简谱下语义完全一致（行号=简谱行，音符序号=行内第 N 个音符）
新增 FR-M7-12 曲目分级元数据谱库支持按 级别/类型/必弹 筛选与排序；选曲页默认显示「学生当前级别」的曲目
新增 FR-M7-13 学生当前级别学生档案增加「当前级别(1–6)」字段，老师可改；布置作业时选曲列表默认过滤该级别、可跨级
新增 FR-M7-14 考级路径（V2）成长页展示考级路径地图：本级必弹※曲目的练习覆盖度；「这一级还差哪首必弹曲没练过」——留作 V2，不进 MVP
FR-M4 考级模拟（远期）原 PRD 的「考级模拟只做三项」设想与此天然衔接，V2 再议，本次不动

模块现状改造

07 · 简谱渲染器技术方案

7.1 渲染目标（对照原书 p16 实际排版）

上图为渲染目标示意（非实现截图）：调号/速度标记、小节线、高低八度点、减时线、增时线、休止 0、批注高亮 + 一句话指令气泡。原书 p16 的实际排版是唯一对照标准。

7.2 数据与交互设计

项设计
谱面载体结构化 token，不用图片。每行 = token 数组；token = 数字 + 八度 + 时值 + 休止，小节线/终止线为行内标点
录入 DSL（内部）给人录的极简文本，如 1=D 中速 | 1 2 3 4 | 3 4 1' 2' | (5 6:轮音) 5 3 | 2 3 5 6_1 6 | 5 3 2 1 ‖——解析器转 token。录入成本主要在这里（§08）
点击批注点任意音符 token → 弹标记面板（与现在五线谱完全同构）；锚定 {li, i} 不变，FR-M7-06 快照机制照常生效
批注显示标记高亮框（朱砂系单色，沿用现有 token）+ 气泡显示一句话指令；孩子端同构
技法符号（V2）轮音⌁、反竹、弹轮、滑弹等原书符号，V1 先用文字标签（现有 MARK_TYPES 扩展），V2 再做符号字形映射——避免 V1 范围膨胀
多声部（V2）5/6 级出现两声部练习（上下两行对齐渲染）。V1 只支持单声部，两声部曲目先「扫描图 + 行级批注」兜底（§12）

08 · 曲目录入策略（最容易被低估的成本）

78 首全部结构化录入不现实也没必要——你只会同时教其中一小部分。建议「占位全量 + 内容分批」：

层内容成本
全量占位（P0，机器做）78 首全部入库，但只有元数据：{级别, 类型, 曲名, 订谱者, 页码, 必弹}——列表可见、可选中的「缺谱态」（灰色 + 「谱面待录入」）脚本一次性生成，0 人工 ⚠6 处曲名由你核对
首批精录（P0，人工）你正在教 / 最常布置的 10–15 首，录入简谱 DSL + 默认 BPM + 演奏提示。建议优先：一级 3–4 首（含五声音阶练习——正好接住现有演示数据）+ 你学生在学各曲每首 15–40 分钟（行数少的练习曲快，乐曲慢）；可由我协助批量转录
渐进补齐（P1+，随教学）每次给真学生布置作业时顺手录一首——录入行为本身发生在上课流程里，不设专门「录完 78 首」的里程碑自然增长
扫描图兜底（可选）缺谱曲目支持上传该页扫描图作为谱面（只读、行级批注定位粗）——个人教学够用每首 1 分钟
版权提醒：原书扫描页只能用于你自己的教学（自用合理）。若产品将来要公开发布/分发给其他老师，谱面必须用「结构化录入」这条路（简谱数字本身不受旋律之外的表达版权保护，但扫描件是出版物复制），且曲目元数据（曲名/订谱者）应保留署名。PRD 应写明这条边界。

09 · 分级体系的产品逻辑（设计优化点）

触点优化
学生档案+「当前级别」。这不是装饰字段——它是老师布置作业时选曲过滤的默认值，也是成长线的坐标系
上课向导 · 选曲默认只看该级别曲目（练习曲/乐曲两个子表）；「看全部级别」折叠在次级操作。选曲成本从「在 78 首里找」降为「在本级 13 首里点」
微目标生成练习曲天然带技法主题（小跳练习→分腕跳音、定拍轮音→轮音均匀）——「从批注生成微目标」可直接继承曲目主题作为技法默认值，减少老师打字
任务卡显示 三级 · 乐曲 · ※喜讯 徽标；家长不用懂考级体系，但能看到「孩子在练第几级什么曲」——进度可视化，呼应「这周的小目标」
回课驾驶舱卡片按曲目级别/类型排布不变，仅加徽标；老师扫一眼知道哪个孩子在攻哪一级
成长页（V2）考级路径地图：本级 25 首必弹中的覆盖度、每首最近一次回课判定；「升级」事件（最后一批必弹全部达标 → 建议进入下一级）

12 · 已知缺口与风险（不装的）

  • 6 处转录不确定（§04 标⚠）：曲名 3 处（蕉石鸣琴 / 黎明舞曲 / 敖西潮 / 杜鹃啼中的不确定者）、改编者 3–4 处。置信度高但非零误差，必须人工核对——原书在你手上，10 分钟的事。
  • ※ 含义未向央音官方求证：「必弹/规定曲目」是行业惯例解读（C 级），落地前以央音当年考级简章为准。
  • 简谱渲染的复杂度长尾：V1 覆盖 音符/八度点/减时线/增时线/休止/小节线/连线（约覆盖书内 90% 记号）；暂不支持：临时升降记号、复杂连音符、多声部对齐、转调——5/6 级部分曲目会踩到，方案是 V1 显式「不支持标记」而不是渲染错。
  • 录入是持续性人力成本：没有「录完」的状态，只有「够教」的状态。靠 P1 的「布置时顺手录」消化，不设集中录入冲刺。
  • 版权边界：扫描图仅自用；对外分发必须走结构化录入（§08）。这条要写进 PRD 非功能需求。
  • 本书版本：PDF 为网店扫描件（水印 jazz100.cn），与正规出版物的页码/曲目应一致，但建议以你手里的正版实体书为最终校对基准。
