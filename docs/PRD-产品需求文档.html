02背景：待解决的数据断链

本产品要解决的是一条四段式数据链上的信息衰减。这不是三个独立痛点，是同一个根因的四个截面。理解这一点是评审后续所有需求的前提。

2.1 问题结构

① 课堂

信息产生：老师发现学生的问题，提出要点

② 课后

指令传递：要点以"群里一句话"形式发出，模糊、不可执行

③ 家庭

执行：家长不懂、孩子不知道怎么练，只能"从头弹一遍"

④ 回课

验证：老师逐个点开视频，无法批量判断，只能重新听一遍

红色节点为断点。第 ④ 个断点用户在最初的需求描述中未提及，但它是前三个的必然结果，也是老师痛感最直接的地方。

2.2 根因

老师的大脑是这条链上唯一的数据库 教学信息只以三种形式存在：老师的记忆、微信群里的一句话、孩子的肌肉记忆。这三种载体都会衰减，且无法被第三方（家长）执行。

推论一：做一个"电子笔记本"没用——记了也没人看。
推论二：做一个"AI 纠错陪练"也没用——红海，且扬琴连续演奏转录无公开数据集（见第 09 节）。

2.3 为什么切入点在"指令传递"

四个断点中，只有第 ② 个同时具备三个条件：它是三个痛点的交汇处、它的改造成本最低、它的收益在第一周就能被感知。

断点能否切入理由
① 课堂数据缺失后置（V1.0）"先付出后收益"——老师第一周感受不到价值就会流失
② 指令传递首选（V0.5）付出 10 分钟（与现在群里打字相同），批改从 50 分钟降到 16 分钟
③ 家庭执行同步（V0.5/V0.8）是 ② 的下游，② 结构化后 ③ 自然可执行
④ 回课验证同步（V0.5）是 ② 的闭环，② 结构化后 ④ 才能批量化

2.4 产品一句话定义

把老师脑子里的东西，变成家长能执行、孩子能对照、老师能验证的"练琴任务卡"。

它不是陪练工具，是教学记忆的外化系统。这个定义决定了后续所有需求的取舍标准：任何不能让信息在链上流动得更好的功能，都不做。

03目标与非目标

非目标（Non-Goals）比目标更重要。本产品已有大量"看起来应该做"的功能被明确排除，评审时若有人提出新增，请先对照这一节。

3.1 产品目标

#目标衡量指标目标值（V1.0 上线后 6 个月）
G1让老师的课后监督成本可量化地下降老师每周处理回课时长从 70 分钟 → ≤ 25 分钟（20 名学生）
G2让家庭练习真实发生并可验证周回课率≥ 60%
G3让孩子知道"怎么练"而不只是"练多久"微目标达成率≥ 75%
G4让老师愿意持续使用老师周活跃留存第 4 周 ≥ 70%
G5验证付费意愿老师付费转化率≥ 15%（阶段二起）

G1 的基线 70 分钟来自第七卷测算：20 名学生 × （发作业 0.5 + 听回课 2.0 + 打字点评 1.0）分钟 = 70 分钟/周。目标值 25 分钟对应"发卡 10 分钟 + 一屏扫 6 分钟 + 重点听 5 人 10 分钟"。

3.2 非目标（明确不做）

不做为什么不做的依据违反的边界
错音 / 音准纠错（连续演奏）扬琴连续演奏无公开数据集；多乐器转录在竞赛场景 F1 仅 0.4367。误报在练琴场景是致命的技术边界（09 节）
综合评分 / 总分音色、乐感不可判定。给出总分等于把不成熟能力包装成完整评价诚实性原则
实时纠错打断技术可行（延迟可做到 380ms 内），但会把 AI 变成"每秒都在说错的电子家长"，只是把冲突从人换成机器动机保护（第 八卷 7.4）
排行榜与物质奖励排行榜触发社会比较焦虑；物质奖励触发过度理由效应，会挤出本就脆弱的内在动机SDT / Deci 1971
AI 自动生成评语老师不点评时留空，而不是用 AI 编。一句假的夸奖比没有夸奖更伤信任信任成本
真人 1v1 陪练撮合师资成本 >60% + 获客 ~50% → 结构性亏损；快陪练、柚子练琴、VIP 陪练、小音咖全灭商业模式（第一卷）
琴行 / 机构 SaaS（排课、收费、CRM）红海，需销售团队，校宝在线已有 26 万+机构。本产品只做"教学"这一段竞争边界
音色 / 姿态 / 表现力评估对应考级五项中的"演奏方法"与"乐感表现"，不可判定技术边界
多乐器同时首发每种乐器的技法词表与微目标库都需要领域专家标注。首版只做扬琴 + 一个对照乐器资源约束
评审纪律 上表九条是有依据的排除，不是"暂时不做"。任何要求新增的请求，必须先说明它推翻了哪一条依据、依据是否仍然成立。若只是"竞品有所以我们也该有"，直接驳回。

04用户角色与权限模型

本产品有四类角色，但只有一类是付费方，只有一类是产品的"用户"（会从中获得乐趣）。混淆这两件事是绝大多数教育产品失败的原因。

4.1 角色定义

角色是谁核心诉求付费产品对它的意义
老师
主客户		 民乐（首期扬琴）个体教师或机构教师 保住学生（留存）、少花时间、显得专业 是（V1.0 起） 工具 + 渠道
孩子
真实用户		 6–15 岁在学学生 知道自己该干什么、被看见、不要被骂 否 唯一会从中获得乐趣的人
家长
付费执行者		 学生父母（多为母亲） 不用当监工、知道进展、不被老师责备 阶段二是 执行者 → 逐步退出
助教 / 机构管理员
V1.1+		 机构内的辅助教学人员 协助批改、查看全机构数据 随机构 后置，本版不做
一条容易被忽略的产品原则 第八卷最重要的修正是：孩子不是被管理的对象，是用户。第七卷把孩子当作数据链的末端（被记录、被催），第八卷把它还原为产品的使用者。

落到设计上的后果：孩子端的每一个界面都必须回答"这对孩子有什么好处"，而不只是"这让家长/老师能看到什么"。凡是只服务监督、不服务孩子的界面，都不得出现在孩子端。

05核心用户旅程

四个旅程覆盖了产品的全部核心路径。评审时请用这四个旅程逐条走查第 07 节的需求，任何旅程走不通的地方都是需求缺口。

5.1 旅程 A：老师布置作业（目标 ≤ 10 分钟 / 周）

步动作系统响应设计意图
1老师进入「本周任务」显示上周任务卡，顶部提示"复制上周并修改"降低启动成本
2选择学生 / 全班支持按"全班统一"或"分组差异化"老师多数时候是全班统一的
3从技法模板库挑选微目标显示扬琴技法词表，选中后自动生成标准表述把"打一段字"变成"点几下"
4设定成功标准默认"5 遍中成功 3 遍"，可改默认值来自第八卷 85% 规则
5（可选）录入一句语音要点语音原样保留，不做转写展示V0.5 不做 ASR，先跑通链路
6发布推送给家长 + 孩子端—
AC-A 老师从进入到发布全程 ≤ 10 分钟（20 名学生的全班统一卡片）。若超过，说明模板库不够用。

5.2 旅程 B：孩子完成练习（目标 ≤ 25 分钟 / 天）

步动作系统响应设计意图
1孩子打开小程序显示"今天要练 3 张卡 · 预计 25 分钟"承诺而非倒计时
2选择一张卡（可换顺序）显示微目标与成功标准满足自主权
3点击"录第 N 遍"开始录音，实时显示遍数进度绑定行为而非时长
4录音结束系统标记"第 N 遍完成"，不判断对错核心边界
5达到成功标准结算页：显示"3/3 遍完成"，提供回放对比胜任感
6全部完成显示今日进度 + 老师留言（若有）归属感
AC-B 孩子完成一张卡的点击次数 ≤ 微目标遍数 + 3。任何多出来的点击都是摩擦。

5.3 旅程 C：老师批改回课（目标 ≤ 25 分钟 / 周）

步动作系统响应设计意图
1老师进入「驾驶舱」一屏显示全班：已练 / 未练 / 遍数 / 时长替代逐个点开
2扫一眼AI 已预标注：练了几次、是否达标准、稳定性趋势把"听"变成"确认"
3挑出 3–5 个重点听只点开这几个的录音80% 的时间节省来自这里
4语音或文字点评点评绑定到具体微目标点评要能被孩子看到
5（可选）一键催未交向家长发送提醒替代群里@所有人
AC-C 20 名学生的批改全程 ≤ 25 分钟，其中"听录音"的时间 ≤ 10 分钟。

5.4 旅程 D：家长陪同 → 退出（V0.5 → V1.0 逐步实现）

步动作系统响应设计意图
1家长收到任务卡首屏固定显示："听不懂没关系，不用您判断对错。"拆解能力焦虑
2家长陪练只显示"第几遍"，不显示对错判断拆解责任焦虑
3家长想了解情况周报：练了几次、达成率、老师留言进度可视化
4长期「家长陪练时长」下降被做成正向成就退出机制（V1.0）
旅程 D 是整个产品最反直觉的设计 绝大多数教育产品在增加家长的参与度（打卡、签到、上传视频）。本产品反其道而行：把家长陪练时长的下降做成正向成就。

理由：家长陪练痛苦的根源不是"累"，是"我不懂还要装懂"。当孩子能通过任务卡独立完成练习时，家长退出是成功而非失职。这一条同时解决了家长痛点与孩子的亲子冲突。

这一节是产品与算法之间的契约。它规定 AI 可以输出什么、不可以输出什么，以及达到什么标准才允许上线。第七卷已证明：准确率是本产品最致命的变量——它的破坏力远大于成本。

准确率门槛不是"越高越好"，而是"错一次都不行" 练琴场景的特殊性在于：误报的代价远高于漏报。把"练对了"判成"练错了"，孩子会困惑、家长会质疑、老师会停用；而把"没练"判成"练了"，最坏情况只是数据虚高。

CREATE TABLE practice_stat (
  submission_id   BIGINT PRIMARY KEY,
  judgement       ENUM('achieved','not_achieved','undetermined') NOT NULL,
                  -- undetermined = 低置信度，系统闭嘴
  played          BOOLEAN,               -- 是否演奏
  completeness    DECIMAL(4,3),          -- 完整性 0-1
  tempo_stability DECIMAL(5,2),          -- 节拍稳定性（方差）
  confidence      DECIMAL(4,3) NOT NULL, -- 置信度，低于阈值置 undetermined
  model_version   VARCHAR(30) NOT NULL,  -- 可追溯

);
judgement 字段的三个值，就是整个产品的价值观 大多数产品只设计两个值（达成 / 未达成）。本产品强制第三个值 undetermined——它在数据库层面保证了"系统可以承认自己不知道"。

这个字段不能被产品经理以"太复杂"为由砍掉。砍掉它，等于砍掉产品最重要的诚实性设计。

11.3 北极星指标

WEPM：周有效练习次数（Weekly Effective Practice Count） 定义：一个学生在一周内完成的有效练习次数（一次 = 一个微目标达成结算）。

为什么不是 DAU：DAU 会奖励"打开但不练"，而系统博弈（Hamari 2014）会让用户精准地优化被激励的指标。
为什么不是时长：Miksza 实验已证明提升来自效率而非时长，且时长极易被"开着 App 干别的"刷高。
